## v0.23.0 — Prometheus metrics, cluster mode, and improved logging

Observability and scalability additions. No breaking changes to the MCP API or plugin interface.

### Features

- **Metrics: Prometheus `/metrics` endpoint.** `GET /metrics` exposes a Prometheus-format scrape endpoint backed by `prom-client`. Ships with default Node.js process metrics (CPU, memory, event-loop lag, GC) plus three custom metric families:
  - `workbench_http_requests_total{method, route, status}` — request counter
  - `workbench_http_request_duration_seconds{method, route, status}` — latency histogram (5ms–5s buckets)
  - `workbench_tool_executions_total{integration, tool, success}` — tool call counter
  - `workbench_tool_execution_duration_seconds{integration, tool, success}` — per-tool latency histogram (50ms–30s buckets), useful for spotting slow integrations

- **Cluster mode: `CLUSTER_ENABLED`.** Set `CLUSTER_ENABLED=true` to fork `os.availableParallelism()` worker processes and utilize all CPU cores. The server guards against running in cluster mode with SQLite (write contention would cause corruption) and exits with a clear error — requires a `postgres://` `DATABASE_URL`. Workers auto-restart on crash.

### Fixes

- **Logging: unredact request URLs.** `req.url` was previously censored in access logs as a precautionary holdover from when tokens appeared in URLs. That pattern was removed long ago; keeping URLs hidden broke request tracing with no remaining security benefit. URLs are now visible in Fastify access logs.

- **Logging: structured tool execution log lines.** Every tool execution via `execute_tool` / `execute_tools` now emits a JSON log line with `user_id`, `integration`, `tool`, `success`, and `duration_ms`. Follows Fastify's pino level convention (30 = info on success, 50 = error on failure) so lines render consistently alongside access logs.
