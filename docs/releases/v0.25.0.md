# workbench v0.25.0

_2026-09-01_

Headline: **Jots gain partial updates, and the documentation is rebuilt as a published site.**

The jots store could only ever be republished whole, which made refreshing one
generated file cost a full re-upload of the site. That is now a patch operation.
Alongside it, the documentation was rewritten from the source and now ships as a
static site on GitHub Pages, replacing a set of Markdown files that had drifted
far enough from the code to mislead.

## Features

- **Partial jot updates: `update_jot` and `list_jot_files`** (`packages/server/src/jots/routes.ts`, `packages/server/src/jots/store.ts`, `packages/server/src/jots/pending.ts`, `packages/server/src/plugins/internal/jots.ts`). `update_jot` mints the same kind of single-use upload token as `deploy_jot`, in patch mode. The server stages a copy of the live tree, applies the token's `delete` list, then overlays the uploaded archive on top, so an uploaded path wins over a delete of itself and files you never mention survive. The archive needs no root `index.html`, because the live one is retained. `list_jot_files` reports a jot's tree so a patch can be targeted. This is what makes a weekly `data.json` refresh cheap.
- **A patch cannot change a jot's gating.** `access` and the password hash are read from the live manifest rather than from the token, and ownership is re-checked when the upload lands rather than trusted from mint time. A jot deleted between mint and upload returns 404; one that changed owner returns 403.
- **Opt-in CORS for public jots** (`cors: true` on `deploy_jot` and `update_jot`). Jot pages run on an opaque origin, which is what stops uploaded JavaScript reaching app cookies, `/api`, `/mcp`, storage, or service workers — and is also why a page could not fetch its own JSON. On a **public** jot the flag serves files with `Access-Control-Allow-Origin: *` and `Cross-Origin-Resource-Policy: cross-origin`, and answers preflight `OPTIONS`. The `sandbox` CSP, `nosniff`, and `X-Frame-Options` headers are unchanged, so no same-origin protection is weakened. The flag is ignored on password jots, because an opaque-origin fetch sends no cookie and would 401 anyway. A preflight to a jot without `cors` returns 404, so CORS posture cannot be discovered by probing.
- **The documentation is now a published site** (`docs/site/`). Every page was rewritten from the source rather than edited, with each factual claim traced back to the code. An audit against the current source found `execute_tool` documented throughout when the meta-tool is `execute_tools`, six of eight provider pages giving an OAuth callback URL that fails at step one, Slack documented as a bot-token integration when the plugin requests user scopes, and `curl_session` — the headline of v0.24.0 — appearing nowhere but a release note. Keycloak SSO, the `apikey` auth mode, the `proxy` and `instance` manifest fields, connected-agent revocation, cluster mode, observability, and the browser-profile reaper were all shipped but undocumented, and are documented now. The generator is `docs/site/build.mjs`: one dependency, no framework, and a build that fails on a broken internal link.

## Fixes

- **The merged jot tree is re-measured against both limits.** `extractTarGzToDir` caps the incoming archive only. Without a second measurement after the overlay, a run of small patches could walk a jot past `JOTS_MAX_BYTES` or `JOTS_MAX_FILES`. An overflowing patch now returns 413 and leaves the live jot untouched.
- **Asset URLs carry a content hash.** Pages serves assets with `cache-control: max-age=600` and the URLs carried no version, so for ten minutes after a deploy a returning visitor got new HTML against old CSS. `assets/docs.css?v=<hash>` changes only when the file changes, so a deploy busts the cache at once. The hash is content-derived, so the build stays reproducible.
- **The docs link checker ignored query strings**, and so reported every versioned stylesheet link as broken. It strips the fragment and the query now.
- **The site build is deterministic.** Tab-group ids came from `Math.random()`, so every run produced different HTML for the same Markdown and the CI staleness check could never pass. They derive from the page path and group index now.
- **Stale tool counts corrected.** The integrations index still described `jots` as 3 tools and the catalog as 190; it is 5 and 192.

## Maintenance

- **Every workflow action moved to its Node 24 major** — `checkout` v4→v7, `setup-node` v4→v7, `configure-pages` v5→v6, `deploy-pages` v4→v5, `upload-pages-artifact` v3→v5, `codecov-action` v4→v7, the four docker actions, and `action-gh-release` v2→v3. Each target declares `using: node24`, verified by reading its `action.yml` at that tag, and every input this repo passes still exists there. The runners were force-running the old majors on Node 24 and warning on every job.
- **The display name is `workbench`**, not `a-workbench`, across the site, the root Markdown files, and the portal UI. The `@a-workbench/*` package scope is unchanged, as is the JWT issuer and audience in `packages/server/src/auth` — rotating those would invalidate every issued token.
- **The docs site was restyled** onto a single token set: one palette, a fixed type scale, a 4px spacing scale, and a derived dark theme. Every text pair clears 4.5:1 contrast in both themes.
- **The site content passes an STE-flavored clarity scan.** 136 semicolons and 63 over-length sentences became short, single-clause sentences, with meaning preserved — net drift across 61,665 words is 6 words.
