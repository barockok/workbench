# workbench v0.26.0

_2026-09-02_

Headline: **Connect links are now claims, not capabilities — account mismatch is rejected before any credential lands in the wrong place.**

The security fix is the headline. A connect link minted for user A could previously be completed by user B, storing B's SaaS credential under A's workbench account. For cookie and browser-session links, any link holder got a working `cdpToken` regardless of identity. This release closes both paths by requiring a matching portal session at every redemption point, replacing three vulnerable bearer-only endpoints with a single gated redeem flow.

Alongside: a CleverTap read-only plugin, Confluence CQL search and attachment listing, and a CI change that stops committing generated docs HTML.

## Security

- **Connect links require a matching portal session.** `connect` / `get_auth_url` and `browser_live_url` now return a claim URL (`/connect/<integration>?t=<jwt>`) with no embedded capability. The provider URL is built and the browser session is warmed only at `POST /api/connect/redeem`, which first checks that the signed-in portal user matches the JWT's `userId`. A mismatch returns `403 ACCOUNT_MISMATCH` and leaves the link unconsumed. See [finding](../findings/2026-09-02-connect-link-account-mismatch.md).
- **`GET /api/connect/session` and `GET /api/connect/browser-session` removed.** These endpoints returned a live `cdpToken` to any link bearer. The single gated `/redeem` endpoint is the replacement; anything that bypasses the session check is gone.
- **CDP WebSocket auth no longer accepts a connect JWT.** `authorizeCdpFrame` now requires a portal session; the integration pin reference it used is dropped.
- **`/connect/:integration` and `/browser` portal pages require auth.** A signed-out visitor is redirected to login, with the destination preserved across SSO, before the redeem attempt is even possible.
- **`POST /api/connect/capture` gets the same session gate.** Cookie capture now verifies the portal session's `userId` matches the connection owner before accepting cookies.
- **Backslash return-path bypass closed.** The portal's post-SSO return-path guard rejected `//` but accepted `\\` as an alternative protocol-relative form; both are now blocked.

## Features

- **CleverTap plugin** (`packages/plugins/clevertap/`). Read-only analytics access. Multi-account config via a JSON key in the connection's secret field — query events, profiles, system events and properties, and predefined profile attributes. Date inputs normalised across `YYYY-MM-DD`, `DD-MM-YYYY` and epoch milliseconds. Reference docs linked from each tool description.
- **Confluence CQL search** (`confluence_search_pages`). Full CQL query support via `POST /wiki/rest/api/search`. The existing title/space search stays; this adds a `cql` parameter for arbitrary CQL expressions.
- **Confluence attachment listing** (`confluence_get_page` → `attachments`). `get_page` now returns an `attachments` array listing filename, media type, size, and download URL for each attachment on the page.
- **Confluence cursor pagination.** `confluence_search_pages` returns `nextCursor` when the server has more results. Pass it back as `cursor` to page past the default limit without re-fetching.

## Fixes

- **Promote script surfaces the tag fetch failure reason.** `scripts/promote-rc.sh` previously printed a generic "fetch failed" message; it now includes the git error detail so a misconfigured remote is diagnosable.

## Maintenance

- **Docs HTML is built in CI, not committed.** `docs/site/_site/` was tracked and every push contained a full site rebuild. The `docs.yml` workflow now runs `node docs/site/build.mjs` and uploads the artifact for GitHub Pages; the generated HTML is gitignored.
