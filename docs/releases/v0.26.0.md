# workbench v0.26.0

_2026-09-05_

Headline: **Connect links are now claims, not capabilities — account mismatch is rejected before any credential lands in the wrong place.**

The security fix is the headline. A connect link minted for user A could previously be completed by user B, storing B's SaaS credential under A's workbench account. For cookie and browser-session links, any link holder got a working `cdpToken` regardless of identity. This release closes both paths by requiring a matching portal session at every redemption point, replacing three vulnerable bearer-only endpoints with a single gated redeem flow.

Alongside: a CleverTap read-only plugin, Confluence CQL search and attachment listing, and a CI change that stops committing generated docs HTML.

Since `rc.2` this release also absorbed the portal revamp: the whole interface moved onto the shared design tokens, and the connect flow an agent starts now has a screen at each end instead of a silent redirect to the dashboard. Base image moves to Node 26, which is why this ships as a release candidate.

## Security

- **Connect links require a matching portal session.** `connect` / `get_auth_url` and `browser_live_url` now return a claim URL (`/connect/<integration>?t=<jwt>`) with no embedded capability. The provider URL is built and the browser session is warmed only at `POST /api/connect/redeem`, which first checks that the signed-in portal user matches the JWT's `userId`. A mismatch returns `403 ACCOUNT_MISMATCH` and leaves the link unconsumed. See [finding](../findings/2026-09-02-connect-link-account-mismatch.md).
- **`GET /api/connect/session` and `GET /api/connect/browser-session` removed.** These endpoints returned a live `cdpToken` to any link bearer. The single gated `/redeem` endpoint is the replacement; anything that bypasses the session check is gone.
- **CDP WebSocket auth no longer accepts a connect JWT.** `authorizeCdpFrame` now requires a portal session; the integration pin reference it used is dropped.
- **`/connect/:integration` and `/browser` portal pages require auth.** A signed-out visitor is redirected to login, with the destination preserved across SSO, before the redeem attempt is even possible.
- **`POST /api/connect/capture` gets the same session gate.** Cookie capture now verifies the portal session's `userId` matches the connection owner before accepting cookies.
- **Backslash return-path bypass closed.** The portal's post-SSO return-path guard rejected `//` but accepted `\\` as an alternative protocol-relative form; both are now blocked.

## Portal

- **A screen before an agent-initiated connect.** `/connect/:integration` used to redeem the link in a mount effect and bounce straight to the provider, so a human who followed an agent's link saw nothing about what was being connected. It now shows the pairing — workbench beside the integration's name and logo — and waits for an explicit accept. Because redeeming consumes the link, this also fixes a real bug: opening the tab and closing it used to burn the link permanently.
- **A result page for every finished connect.** New `/connected/:integration?status=…`, where both the provider callback and the cookie-capture flow now land. Previously the callback redirected to `PORTAL_URL#connected=<x>`, a fragment nothing in the portal read, so a successful authorisation ended on the dashboard with no confirmation.
- **Failures say what happened without leaking why.** The callback redirects with one of `ok`, `denied`, `expired` or `failed`. The provider's own error text and any exception message stay in the server log — both are attacker-influenced and that URL is shown to a person. Previously a provider error replied with raw JSON in the browser window.
- **The interface runs on the shared design tokens.** `packages/shared/styles/tokens.css` is now the single source for colour, spacing and type across the portal and the docs site, with one geometry decision (a single radius, shadows reserved for the modal) enforced by a stylesheet guard test.
- **One brand system.** The mark — a lowercase `w` in an outline tile on the accent — is now drawn the same way in the portal and the docs site, assembled through one lockup component. The sidebar and the login hero carry it for the first time. Both favicons were also silently broken: `docs/site/build.mjs` URL-encodes the SVG from `nav.json`, which already spelled its colours as `%23rrggbb`, so the double encoding reached the browser as a literal string instead of a colour and the mark rendered as a black letter on nothing.

## Features

- **CleverTap plugin** (`packages/plugins/clevertap/`). Read-only analytics access. Multi-account config via a JSON key in the connection's secret field — query events, profiles, system events and properties, and predefined profile attributes. Date inputs normalised across `YYYY-MM-DD`, `DD-MM-YYYY` and epoch milliseconds. Reference docs linked from each tool description.
- **Confluence CQL search** (`confluence_search_pages`). Full CQL query support via `POST /wiki/rest/api/search`. The existing title/space search stays; this adds a `cql` parameter for arbitrary CQL expressions.
- **Confluence attachment listing** (`confluence_get_page` → `attachments`). `get_page` now returns an `attachments` array listing filename, media type, size, and download URL for each attachment on the page.
- **Confluence cursor pagination.** `confluence_search_pages` returns `nextCursor` when the server has more results. Pass it back as `cursor` to page past the default limit without re-fetching.

## Fixes

- **Promote script surfaces the tag fetch failure reason.** `scripts/promote-rc.sh` previously printed a generic "fetch failed" message; it now includes the git error detail so a misconfigured remote is diagnosable.

## Maintenance

- **Base image moves to Node 26.** `Dockerfile` and `Dockerfile.sample-oauth` bumped from Node 20. This is the change that makes the release a candidate: per the release policy anything touching the Docker image soaks as `-rc.N` before `latest` moves.
- **Internal references removed from the repository and its history.** Two references named an external integration by its internal project name; one sat in `docs/findings/`, which the site publishes, so it was live on the public docs site and in its search index. Both are rewritten, and the corresponding strings were scrubbed from history along with a stale MCP client config that named an internal environment.
- **GitHub Actions pinned to commit SHAs.** All eleven actions used floating tags; a retagged or compromised action would have run with `GITHUB_TOKEN` and the registry credentials the release workflow holds. The tag is kept alongside each SHA as a comment.
- **Dependabot enabled.** Nothing was watching dependencies. Grouped by production and development so a week's patches arrive as one reviewable pull request, with the Docker base image and GitHub Actions covered too.
- **Coverage upload no longer fails Dependabot builds.** `fail_ci_if_error: true` turned the missing `CODECOV_TOKEN` on Dependabot pull requests into a red build after the tests had already passed. The upload now runs only when a token is present.

- **Docs HTML is built in CI, not committed.** `docs/site/_site/` was tracked and every push contained a full site rebuild. The `docs.yml` workflow now runs `node docs/site/build.mjs` and uploads the artifact for GitHub Pages; the generated HTML is gitignored.
