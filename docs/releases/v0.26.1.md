# workbench v0.26.1

_2026-09-05_

Headline: **v0.26.0's container could not start.** It exited on
`Cannot find module 'tar-stream'`, having already reported the OpenTelemetry
SDK missing. This release fixes the image; nothing else changed.

## Fixes

- **The image ships the workspace's nested dependencies.** The runtime stage
  copied only `/app/node_modules`, which assumed npm always hoists a workspace's
  dependencies to the root. It does not — a version that cannot hoist stays under
  `packages/<pkg>/node_modules`. v0.26.0 moved enough of the dependency tree that
  five of the server's runtime dependencies ended up there (`tar-stream` and four
  `@opentelemetry` packages), present in the builder and absent from the image.
  Node resolves `server/node_modules` before `/app/node_modules`, so the nested
  tree is now copied alongside the compiled output, where the server already
  looks for it.

## Why the release process missed it

The v0.26.0 release run passed its tests, built the image and pushed it — but
nothing ever started the container. Build success is not start success, and this
release is the proof. A smoke step that runs the built image and waits for it to
listen would have caught it before the tag moved.
